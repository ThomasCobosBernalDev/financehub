The data is already there. Learn to ask it questions.

The story so far The bike chain (Lessons 16.1 to 16.3) saves every sale in a database: which store, which month, how much. Your manager asks: "How much did Austin sell this quarter?" Nobody emails you a spreadsheet. The answer sits in a table with millions of rows, and the way to get it is SQL, a language for asking databases questions. Almost every bank, fund and company keeps its data this way, and SQL is one of the skills finance job posts ask for most.

What

SQL (say "sequel" or "S-Q-L") is a language for pulling data out of a database: the rows you want, added up the way you want.

Why

Company data is too big for a spreadsheet. SQL fetches just what you need, often in seconds, from millions of rows.

How

You write a query: SELECT the columns, FROM a table, WHERE rows match a rule, then sort, count or add them up.

Who

Data analysts and FP&A analysts pull reports with it. Risk and compliance teams search trades. Quants load prices before using Python.

A database is a set of tables.

A database keeps data in tables. Each row is one record, like one sale; each column is one kind of fact, like the store or the amount. SQL is how you ask for it, and each question is a query. Here is the chain's sales table for one quarter. A real one has millions of rows; the rules are the same.

SELECT, FROM and WHERE

Every query starts with SELECT (which columns) and FROM (which table). * means every column. WHERE keeps only the rows that pass a test. Text goes in single quotes, like 'Austin', and a semicolon ends the query. AND joins two tests: a row must pass both. > means more than and < means less than; a value equal to the number doesn't pass.

SELECT month, amount FROM sales WHERE store = 'Austin';Jan 1200 Feb 1400 Mar 1300
In this example
SELECT month, amount
Only those two columns come back.
WHERE store = 'Austin'
Keeps 3 of the 9 rows.
Add AND amount > 1250
Only Feb (1400) and Mar (1300) pass both tests.

ORDER BY and LIMIT

ORDER BY sorts the results; add DESC for biggest first. LIMIT keeps only the first few rows. Together they answer "what were our top 3?"

SELECT store, month, amount FROM sales ORDER BY amount DESC LIMIT 3;Miami Mar 1700 Miami Feb 1600 Miami Jan 1500
In this example
The top 3 months
All Miami: 1700, 1600 and 1500.

Adding up: COUNT, SUM, AVG and GROUP BY

SQL can summarize as it fetches. COUNT(*) counts rows, SUM() adds a column, and AVG() averages it. GROUP BY splits the rows into groups first, so you get one answer per group, like a totals row for each store.

SELECT store, SUM(amount), AVG(amount) FROM sales GROUP BY store;Austin 3900 1300 Denver 2700 900 Miami 4800 1600
In this example
COUNT(*) FROM sales
9 rows.
Austin's SUM
1200 + 1400 + 1300 = 3900, the answer to your manager's question.
Austin's AVG
39003 = 1300 a month.

JOIN: connect two tables

Databases split data into many tables so nothing is typed twice. JOIN puts them back together by matching a column they share.

SELECT stores.manager, SUM(sales.amount) FROM sales JOIN stores ON sales.store = stores.store GROUP BY stores.manager;Kim 2700 Lopez 4800 Rivera 3900
In this example
The stores table
Austin: manager Rivera. Denver: Kim. Miami: Lopez.
Matched on store
Each sale finds its store's manager, so Lopez's stores sold 4800.

The order clauses go in

SELECT → FROM → JOIN → WHERE → GROUP BY → ORDER BY → LIMIT

You can skip any clause you don't need, but the ones you use must go in this order.

Worked example: Denver's slow months

The regional manager asks: "Which months did Denver sell less than $1,000?" Here are the facts:

  • The table: sales, with store, month and amount.
  • Two tests: the store is Denver, and the amount is under 1000.
  • Wanted: the months, smallest first.
SELECT month, amount FROM sales WHERE store = 'Denver' AND amount < 1000 ORDER BY amount;Feb 700 Jan 900
  1. Table. FROM sales.
  2. Rows. Denver has Jan 900, Feb 700 and Mar 1100. With AND, both tests must pass, so Mar drops out.
  3. Sort. ORDER BY amount with no DESC puts the smallest first.
  4. The answer. February ($700) and January ($900). Denver picked up in March ($1,100), which is worth telling the manager too.

A bird that queries its memory.

Each fall, a Clark's nutcracker, a bird of western mountains, hides tens of thousands of pine seeds in thousands of small caches spread across the slopes. Months later, often under snow, it flies back and digs up the right spots, using rocks and trees as landmarks.

What you're looking at: an illustration, not data. Brown dots are seed caches hidden across a slope; the green circles are the few the nutcracker is digging up today.

Why this sticks. The bird doesn't dig up the whole mountain; it goes straight to the caches it wants. A good query does the same: the database holds everything, and WHERE takes you straight to the rows you need.

On the job: you're a data analyst at the bike chain

The CFO is meeting store managers tomorrow and sends you a message: "Which store had the highest total sales this quarter, and what was its average month?" Here's what you have:

  • The table: sales, with store, month and amount (the 9 rows in this lesson).
  • Wanted: one row, with the store, its total and its average.

Your task: write one query that answers both, and the reply you'd send.

See a model answer
SELECT store, SUM(amount), AVG(amount) FROM sales GROUP BY store ORDER BY SUM(amount) DESC LIMIT 1;Miami 4800 1600

To the CFO: Miami led the quarter with $4,800 in sales, an average of $1,600 a month, and it grew every month (1500, 1600, 1700). Austin was second at $3,900.
